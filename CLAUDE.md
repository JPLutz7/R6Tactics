# Operating rules

## Verify, don't answer from memory
**Always verify a checkable claim before stating it — do not rely on memory.**
This applies to anything externally checkable: Rainbow Six Siege facts (operator
loadouts, gadgets, reworks, bans, current meta, map geography), library/API
behavior, pricing, versions, current events — and facts about this repo.

- Use the right tool: **WebSearch / WebFetch** for game/world facts; **Read /
  Grep / Glob** for code and repo facts. Prefer primary/authoritative sources.
- This includes *corrections*: before "fixing" something an agent or teammate
  wrote because it "looks wrong," verify it's actually wrong first. (We once
  removed Pulse's **Reaper MK2** as a "hallucination" — it's a real Y10S3
  secondary. See HANDOFF §15.)
- When a fact genuinely can't be verified from here, **say so and flag the
  uncertainty** instead of asserting it. Don't pad with confident guesses.
- This is about correctness, not ceremony — you don't need a web search to know
  the obvious; verify when a claim is checkable, consequential, or you're not
  sure.
